# 10. 반응형 레이아웃

## 목표

같은 코드가 세로 긴 휴대폰, 가로 넓은 데스크탑, 임의 크기의 브라우저 창에서 모두 제대로 보이게 한다.

## 선행 조건

- [04-game-screen.md](completed/04-game-screen.md)

## 작업

### 1. 원칙

**보드가 주인공이다.** 가용 공간에서 보드가 최대한 크되 정사각을 유지하고, 남는 공간에 HUD 를 배치한다.
조작은 판 위에서 직접 하므로(스와이프 · 방향키 · 드래그) 컨트롤에 자리를 내줄 필요가 없다.

플랫폼(`Platform.isAndroid` 등)이 아니라 **가용 폭**으로 분기한다. 브라우저 창을 좁히면 모바일 레이아웃이 되어야 하고, `dart:io`는 웹에서 못 쓴다.

### 2. 브레이크포인트

**가로 배치(expanded)는 하지 않기로 했다.** 앱이 세로 고정이고(기획서 §6.2) HUD 에 있는 것이 이동 횟수와 다시하기뿐이라 우측 패널이 성립하지 않는다. 넓은 창에서는 보드가 `maxBoardExtent` 에서 멈춘 채 가운데 놓이고 HUD 가 그 폭을 따라가면 그것으로 충분하다.

| 이름 | 폭 | 레이아웃 |
|---|---|---|
| 전 구간 | — | 세로 배치: 보드 → 하단 HUD. HUD 폭 = 보드 폭 |

즉 이 작업에 남은 것은 **레이아웃 분기가 아니라 극단적인 크기에서 깨지지 않는지 검증**이다.

`LayoutBuilder`로 판정한다. `MediaQuery` 전체 크기가 아니라 **부모가 준 제약**을 기준으로 해야 중첩 레이아웃에서 깨지지 않는다.

### 3. 보드 크기

**이미 `04` 에서 구현되어 있다** (`BoardView`). 이 작업에서 새로 짜지 말고 필요한 만큼만 손본다.

```
extent = min(가용폭, 가용높이, AppConstants.maxBoardExtent)
셀 크기 = extent / (max(행수, 열수) + 2 × Spacing.wallWidthRatio)
```

나눗수에 붙는 항은 격자 **바깥**에 외곽 프레임이 들어갈 여백이다. 이 여백을 빼먹고 계산하면 프레임이 가장자리 칸을 파고들어 그 칸만 여백이 비대칭이 된다 (실제로 났던 버그다).

- 셀은 항상 정사각. 6×6도 8×8도 화면에서 같은 외곽 크기를 갖게 하면 레벨 간 이동이 안정적으로 보인다.
- **최대 크기 상한**은 `AppConstants.maxBoardExtent`(640px). 대형 모니터에서 보드가 화면을 다 먹으면 시선 이동이 커져 오히려 불편하다.
- **아직 없는 것:** 최소 셀 크기 하한(예: 32px). 그보다 작아지면 스크롤 대신 여백을 줄인다.
- 좌표 계산은 `BoardView` 한 곳에만 둔다. `BoardPainter` 는 `cell` 과 `origin` 을 받아 쓴다 — 두 곳에서 각자 계산하면 언젠가 어긋난다.

### 4. 안전 영역

- `SafeArea`로 노치·홈 인디케이터 회피
- 하단 HUD 가 홈 인디케이터에 가리지 않는지 실기기에서 확인
- 데스크탑 창을 극단적으로 작게 만들어도 오버플로가 나지 않아야 한다

### 5. HUD 배치 — **완료**

**화면 방향 버튼은 없다** (기획서 §6). HUD 에 있는 것은 이동 횟수와 다시하기뿐이라 배치 부담이 작다.

보드 아래 한 줄로 두고 **폭을 보드 폭에 맞춘다** (기획서 §6.2). 계산은 `BoardMetrics.fit` 한 곳에 있고 `BoardView` 와 화면이 같이 부른다.

남은 한 가지: `Column` 이 HUD 를 보드보다 **먼저** 배치하므로 화면 쪽 계산에는 HUD 자신의 높이가 빠져 있다. 폭이 짧은 변이면 높이가 결과에 관여하지 않아 정확하고, **가로로 납작한 창에서만 HUD 가 보드보다 조금 넓다.** 세로 고정이라 실기기에서는 나지 않는다.

### 6. 레벨 선택 그리드

`SliverGridDelegateWithMaxCrossAxisExtent(maxCrossAxisExtent: 140)` 등으로 폭에 따라 열 수가 자동 결정되게 한다. 고정 `crossAxisCount`를 쓰지 않는다.

### 7. 웹 특이사항

- 브라우저 확대/축소(`textScaleFactor` 포함)에서 레이아웃이 깨지지 않는지
- 창 리사이즈 중 매 프레임 재계산이 발생하므로 `shouldRepaint`가 과하게 참을 반환하지 않는지
- 초기 로딩 시 흰 화면 시간 확인 (해결은 별도 과제)
