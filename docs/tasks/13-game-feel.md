# 13. 게임다운 손맛

## 목표

`12` 에서 화면이 게임처럼 **보이게** 됐다. 이번에는 **만졌을 때 게임처럼 느껴지게** 한다.

일곱 갈래다 — 스플래시 속도, 카드 모양, 버튼 모양, 다이얼로그 등장, 별 하나씩 등장, 튜토리얼 데모, 막힌 블록의 쫀득거림.

## 선행 조건

- [12-ui-polish.md](completed/12-ui-polish.md) — 여기서 만든 `OverlayCard` · `BoardPreview` · 블랙홀 페인터를 그대로 쓴다

## 착수 전에 읽을 것

**모양은 이미 골랐다.** 임시 갤러리(`lib/dev/`)에 세 안씩 만들어 눈으로 고른 결과다.

| | 정한 것 |
|---|---|
| 카드 | **N1 각진 네온** — 모서리를 깎고 테두리가 별 개수만큼 빛난다 |
| 버튼 | **C 각진** — `BeveledRectangleBorder`, 누르면 안쪽이 밝아지며 살짝 줄어든다 |

**둘이 같은 언어를 쓰는 것이 요점이다.** 어느 하나만 각지면 어긋나 보인다. 그래서 §7의 마지막 일은 **`lib/dev/` 와 임시 라우트를 지우는 것**이다.

**§7(쫀득거림)은 규칙 문서를 건드린다.** 기획서 §3.2의 "무효 입력은 상태를 바꾸지 않는다" 는 그대로지만, **화면이 그 사실을 알아야** 한다. 코드보다 `docs/game-design.md` 를 먼저 고친다.

## 1. 스플래시를 느리게

지금 블록 슬라이드가 0.6초라 **눈으로 따라가기 전에 끝난다.**

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 블록 슬라이드 | 0.6초 | **1.1초** |
| 제목 페이드인 | 0.4초 | 0.5초 |
| 전체 | 1.8초 | **2.8초** |

- 커브는 `easeOutBack` 그대로 — 끝에서 살짝 되튕겨 "부딪혀 멈췄다" 로 읽힌다. 느려지면 이 되튕김이 비로소 보인다.
- **누르면 즉시 넘어가는 것은 그대로다.** 두 번째부터 2.8초를 기다릴 이유가 없고, 이것이 있어서 시간을 늘릴 수 있다.
- 블록이 **하나씩 차례로** 도착하게 한다(뒤 블록일수록 조금 늦게). 지금은 계수만 다르고 동시에 끝나서 한 덩어리로 보인다.

## 2. 레벨 카드 — 각진 네온

```
╔═══════════════╗   모서리를 깎은 사각형 (BeveledRectangleBorder)
║  · · · · ·    ║   테두리 2px + 바깥 글로우
║  · ■ · · ·    ║
║  · □ · # ·    ║   별 3개 → tertiary, 가장 강한 빛
║  · · ◎ · ·    ║   별 2개 → primary
║  1 미끄러지기   ║   별 1개 → secondary
║   ★★★  1수    ║   미클리어 → 회색 테두리, 글로우 없음
╚═══════════════╝   잠김 → 실루엣 + 회색
```

- **바탕은 어둡게 하지 않는다.** 표면색에 그 빛을 5%만 섞어 안쪽에 옅은 색감만 돈다 — 어두운 바탕은 지금 테마와 어긋난다(실제로 만들어 보고 물러섰다).
- 빛 색을 **값으로 박지 않고 `ColorScheme` 에서 뽑는다.** 다크 테마에서 금색이 탁해지는 문제를 `12` 에서 같은 방법으로 피했다.
- 레벨 이름을 빛 색으로 물들인다.
- 누르면 0.95배.

`12` 에서 넣은 `_medalColor` 는 이 글로우 색으로 흡수된다 — 테두리 색과 빛 색이 따로 놀 이유가 없다.

## 3. 버튼 — 각진 안 하나로 통일

**앱의 모든 버튼**이 대상이다. Material 기본(`FilledButton` · `OutlinedButton` · `TextButton.icon` · `IconButton`)을 그대로 두지 않는다.

| | |
|---|---|
| 모양 | `BeveledRectangleBorder`, 모서리 10 |
| 테두리 | 1.5px `outline` |
| 누를 때 | 안쪽이 `surface` 쪽으로 25% 밝아지며 **0.97배**로 줄어든다 (80ms) |
| 비활성 | 채움·테두리 모두 흐리게, 반응 없음 |

### 어디에 두는가

**`core/widget/` 에 공용 위젯으로 둔다.** 지금 이 폴더가 없으므로 새로 만든다.

```
lib/core/widget/
├── game_button.dart        주 · 보조 버튼
└── game_icon_button.dart   아이콘 전용
```

feature 가 아니라 `core` 인 이유: `game` · `level` · `settings` 세 feature가 모두 쓴다. feature 하나에 두면 나머지 둘이 그것을 import 해야 하고, 그 순간 **feature 간 간선이 모양 때문에 생긴다.**

### 바꿀 자리

| 파일 | 무엇 |
|---|---|
| `result_overlay.dart` | 목록으로 · 다시하기 · 다음 레벨 |
| `tutorial_overlay.dart` | 시작 |
| `game_hud.dart` | 다시하기(아이콘+글자) |
| `game_play_screen.dart` | AppBar 뒤로가기 |
| `level_select_screen.dart` | AppBar 설정 |
| `settings_dialog.dart` · `language_picker_dialog.dart` | 목록 항목과 확인·취소 |

**AppBar 안의 아이콘까지 바꾼다.** 한 화면에서 어떤 버튼은 각지고 어떤 버튼은 Material 기본이면 그게 제일 어색하다.

## 4. 다이얼로그 등장 — 튕기듯

지금 `OverlayCard` 는 0.9 → 1.0, `easeOutBack`, 180ms 다. 되튕김이 거의 안 보인다.

- **0.82 → 1.0, `elasticOut`, 420ms.**
- 스크림은 같은 시간 동안 함께 어두워진다(지금은 즉시 나타난다).

`OverlayCard` 한 곳만 고치면 **결과와 튜토리얼이 같이 바뀐다** — `12` 에서 둘을 합쳐 둔 값이 여기서 나온다.

설정·언어·확인 다이얼로그는 `showDialog` 를 쓰므로 `transitionBuilder` 를 따로 넘겨 같은 커브를 태운다.

## 5. 별이 하나씩 등장

### 무엇을

```
클리어!                클리어!                클리어!
                        ★                     ★ ★ ★
[목록] [다시] [다음]   [목록] [다시] [다음]   [목록] [다시] [다음]
        (비활성)              (비활성)              (활성)
```

- 별 하나가 **튀어나오듯**(`elasticOut`, 0.0 → 1.2 → 1.0) 등장한다. 사이 간격 **220ms**.
- 얻지 못한 별도 같은 리듬으로 등장하되 **빈 별 모양**이다 — 세 칸이 다 채워지는 리듬이 있어야 "3개 중 2개" 가 읽힌다.
- **다음 레벨 버튼은 연출이 끝날 때까지 비활성이다.** 요청의 핵심이다.

### 왜 비활성인가

버튼을 아예 늦게 **나타나게** 하면 그때 레이아웃이 밀려 다른 버튼 위치가 흔들린다. 자리는 처음부터 잡아두고 **활성만 늦춘다.**

**목록으로 · 다시하기는 처음부터 활성이다.** 별 연출을 다 보지 않고 나갈 자유는 남긴다.

**실패 다이얼로그에는 별이 없으므로 지연도 없다.**

## 6. 튜토리얼 상단 데모

### 무엇을

그 레벨에서 처음 나오는 규칙을 **문구 위에서 움직여 보여준다.** 2~3초짜리 장면이 **자동으로 계속 반복**된다 — 누를 것이 없고, 놓쳐도 다시 본다.

| 레벨 | 배우는 것 | 데모 |
|---|---|---|
| 1 | 미끄러짐 | 블록이 벽까지 미끄러져 목표에 멈춘다 |
| 3 | 블록 브레이크 | 앞 블록이 먼저 멈추고 뒤 블록이 그 앞에 선다 |
| 5 | 블랙홀 | 블록이 블랙홀 위를 **지나가다** 빨려 들어간다 |
| 7 | 경계 벽 | 블록이 경계 벽 앞에서 멈추고, **벽 양쪽 칸은 멀쩡하다** |

### 어떻게

- **`TutorialDemo` enum 을 `Level` 에 둔다.** `hasTutorial`(bool)이 이것으로 바뀐다 — `null` 이면 안내가 없는 레벨이다.
  - 어느 레벨이 무엇을 가르치는지는 **레벨 설계의 사실**이라 번역이 아니라 데이터다. `11` 에서 `hasTutorial` 을 만든 이유와 같다.
- 데모 위젯은 **`game` 이 소유한다** — 판을 그리므로. 튜토리얼 오버레이도 `game` 에 있어 새 간선이 없다.
- 작은 판을 `BoardPreviewPainter` 로 그리고 블록만 위젯으로 얹어 움직인다. **실제 이동 엔진을 태우지 않는다** — 데모는 정해진 장면이지 시뮬레이션이 아니다.
- 반복 재생이므로 `AnimationController.repeat()` 가 필요하다. 블랙홀 회전에 이어 **두 번째 컨트롤러**다.
  - `pumpAndSettle` 이 끝나지 않으므로 튜토리얼이 뜬 화면을 그 방식으로 검사하면 멈춘다. `12` 에서 겪은 것과 같고, 코드에 같은 주의를 남긴다.
  - `MediaQuery.disableAnimationsOf` 면 마지막 장면에서 멈춘다.

## 7. 막힌 블록의 쫀득거림

### 언제

**아무 블록도 못 움직일 때만** — 즉 무효 입력일 때다. 유효한 수에서 벽에 붙은 블록은 조용히 있는다.

```
→ 를 눌렀는데 아무도 못 움직임

[#][@][O]        오른쪽이 막혀 있다
    ⇔  ⇔         판 위 모든 블록이 그 방향으로 살짝 밀렸다 돌아온다
```

- 밀리는 거리 **셀의 12%**, 갔다 오는 데 **200ms**, `Curves.easeOut` → `easeIn`.
- **이동 횟수는 올라가지 않는다.** 기획서 §3.2의 무효 입력 규칙은 그대로다.
- 연속으로 누르면 **다시 재생한다**(쌓이지 않는다).

### ⚠ 무효 입력이 이제 화면에 보인다

지금 `_applyMove` 는 `if (!result.moved) return;` 으로 **아무 흔적도 남기지 않는다.** 화면이 흔들리려면 그 사실이 상태에 나타나야 한다.

- `GamePlayScreenState` 에 `bumpedDirection` 과 세대 카운터를 둔다.
  - **방향이 필요하다** — 어느 쪽으로 밀렸다 돌아올지가 달라진다.
  - **카운터가 필요하다** — 같은 방향을 두 번 누르면 상태가 같아 `AnimatedX` 가 다시 재생하지 않는다.
- `isAnimating` 은 세우지 **않는다.** 쫀득거리는 동안에도 다른 방향은 즉시 받아야 한다.

기획서 §3.2에 "무효 입력은 상태를 바꾸지 않되 **화면은 막혔음을 알린다**" 한 줄을 더한다.

## 열린 질문 / 미결정 사항

- **쫀득거림에 소리나 진동을 붙일지.** 촉각 피드백(`HapticFeedback.lightImpact`)은 한 줄이면 되지만 소리는 에셋과 볼륨 설정이 따라온다. 이번에는 넣지 않는다.
- **데모를 레벨 2·4·6에도 붙일지.** 지금은 새 규칙이 나오는 1·3·5·7에만 안내가 있다. 데모가 재미있으면 나머지에도 붙이고 싶어질 수 있으나, **이미 배운 것을 되풀이하면 읽지 않게 된다**(기획서 §6.1).
- **각진 모양을 보드에도 적용할지.** 블록은 지금 둥근 모서리다. 카드·버튼이 각져도 판은 부드러운 편이 대비가 살 수 있어 이번에는 건드리지 않는다.
- **버튼을 `core/widget/` 에 두는 것이 맞는지.** 테마(`ButtonStyle`)로 푸는 방법도 있으나, 누를 때의 축소·밝아짐은 `ButtonStyle` 로 표현하기 번거롭다. 위젯으로 가되 색·모서리 값은 테마에서 뽑는다.
- **CJK 글꼴 두부 문제**는 여전히 미확인이다 (`10-responsive` 에서 넘어온 것).
