# 12. UI 디테일 개선

## 목표

기능은 다 됐다. **게임처럼 보이게** 만든다.

여섯 갈래다 — 스플래시, 레벨 선택 그리드, 설정 다이얼로그, 플레이어·목표 색, 블랙홀 연출, 오버레이 카드(결과 · 튜토리얼).

- [10-responsive.md](completed/10-responsive.md) — 카드가 커지면 열 수가 바뀐다. 반응형 테스트가 그것을 잡는다

## 착수 전에 읽을 것

**이 작업은 규칙 변경을 포함한다** — `구멍` 이 `블랙홀` 이 된다(§5). `docs/game-design.md` 를 **코드보다 먼저** 고친다.

**`level → game` 간선을 만들면 안 된다**(§2). 미니 보드 미리보기가 바로 그 유혹이며, 우회로가 §2에 있다.

## 1. 스플래시

### 무엇을

앱을 켜면 제목이 뜨고, 블록이 미끄러져 들어와 제자리에 멈추는 짧은 연출 뒤 레벨 선택으로 넘어간다.

```
        ┌──────────────────────┐
        │                      │
        │   ■ □ □ ▣            │   ← 블록이 왼쪽에서 미끄러져 와
        │                      │      목표 칸에 "탁" 멈춘다
        │    BlockRunner       │   ← 제목은 페이드인
        │                      │
        └──────────────────────┘
```

연출이 곧 게임 규칙의 요약이다 — 미끄러지고, 멈추고, 목표에 선다. 로고를 새로 만들 것 없이 게임 자체가 로고다.

### 어떻게

| | |
|---|---|
| 위치 | `lib/feature/splash/presentation/splash/` — Root + Screen. **domain · data 가 없다** (`progress` 에 `presentation` 이 없는 것과 같은 종류의 생략) |
| 라우트 | `RoutePaths.splash = '/'` 를 새 `initialLocation` 으로. 끝나면 `context.go(levelSelect)` — `push` 가 아니라 `go` 다. 뒤로가기로 스플래시에 돌아오면 안 된다 |
| 시간 | 총 **1.8초**. 블록 슬라이드 0.6초 → 제목 페이드인 0.4초 → 머무름 0.8초 |
| 건너뛰기 | **화면을 누르면 즉시 넘어간다.** 두 번째부터는 기다릴 이유가 없다 |
| 애니메이션 | `AnimationController` 를 쓰지 않는다. `TweenAnimationBuilder` · `AnimatedOpacity` + `Timer` — `06-animation` 에서 정한 방식 그대로 |
| feature 의존 | `splash → (없음)`. 보드를 그리지 않고 사각형 몇 개를 직접 그린다 |

### 하지 않는 것

- **네이티브 런치 스크린(Android `launch_background.xml` · iOS `LaunchScreen.storyboard`)은 손대지 않는다.** 인앱 스플래시와 별개 문제이고, 플랫폼별 파일을 6벌 고쳐야 한다.
- **웹 초기 로딩 흰 화면도 이 작업이 아니다.** `index.html` 이 Flutter 부팅 전에 무언가를 보여줘야 하는 문제라 결이 다르다 (`10-responsive` §7에도 별도 과제로 적혀 있다).

## 2. 레벨 선택 그리드

### 무엇을

**카드 자체를 화려하게** 하고, **카드 안에 그 레벨의 판을 작게 그린다.**

```
┌───────────────┐   ┌───────────────┐   ┌───────────────┐
│ ░░▓▓██▓  금색 │   │ ░░▓▓██▓  은색 │   │▓▓▓▓▓▓▓▓ 어둡게│
│  · · · · ·    │   │  · · · · ·    │   │               │
│  · ■ · · ·    │   │  · · ▣ · ·    │   │      🔒       │
│  · □ · · ·    │   │  · ■ · # ·    │   │               │
│  · · ▣ # ·    │   │  · · · · ·    │   │     잠김      │
│ 1  Sliding    │   │ 2  The Wall   │   │               │
│  ★★★  1 move  │   │  ★★☆  3 moves │   │               │
└───────────────┘   └───────────────┘   └───────────────┘
   ↑ 별 뒤 글로우      ↑ 미니 보드          ↑ 실루엣만
```

- **미니 보드** — 그 레벨의 초기 판. 무엇을 푸는 판인지 한눈에 보인다.
- **잠긴 레벨은 판을 실루엣으로만** 그린다. 판 모양이 곧 스포일러라, 이름을 가린 것(`08`)과 같은 이유다.
- **별 개수에 따라 카드 테두리 색이 달라진다** — ★★★ 금색, ★★☆ 은색, ★☆☆ 동색, 미클리어는 없음. 목록을 훑을 때 성취가 색으로 읽힌다.
- ★★★ 카드는 별 뒤에 옅은 글로우.
- 누르면 살짝 눌리는 반응(`AnimatedScale` 0.96).

### ⚠ 미니 보드가 순환 의존을 부른다

**판은 `game` 이 소유하고 레벨 선택 화면은 `level` 에 있다.** 카드가 판을 그리려면 `level → game` 이 필요한데 `game → level` 이 이미 있다 — **`#22` 에서 끊었던 바로 그 순환이다.**

`Level` 에 판을 도로 넣는 것도 답이 아니다. 그것이 애초에 `#22` 의 원인이었다.

**우회로: 미리보기 위젯을 `level` 이 만들지 않고 받는다.**

```dart
// level feature — game 을 모른다. 타입에 game 이 새어나오지 않는다.
class LevelSelectScreen extends StatelessWidget {
  final Widget Function(BuildContext, int levelNumber, bool isUnlocked) previewBuilder;
}

// core/router — 이미 두 feature 를 다 import 하고 있는 유일한 곳이다.
GoRoute(
  path: RoutePaths.levelSelect,
  builder: (context, state) => LevelSelectRoot(
    previewBuilder: (context, number, unlocked) =>
        BoardPreview(levelNumber: number, isSilhouette: !unlocked),
  ),
)
```

`BoardPreview` 는 `game` 소유이며 `BoardPainter` 를 작은 크기로 재사용한다(블록 위젯 없이 페인터만 — 미리보기는 움직이지 않는다).

**조립을 라우터가 하는 것이 핵심이다.** 라우터는 원래 모든 feature 를 아는 자리이고, `level` 은 `Widget Function(...)` 이라는 순수 Flutter 타입만 본다.

### 파급

- **카드가 커지므로 `maxCrossAxisExtent` 와 `childAspectRatio` 를 다시 잡아야 한다.** 미니 보드가 정사각이라 카드는 지금보다 세로로 길다.
- **열 수가 줄면 카드 폭은 늘어난다** → 레벨 이름 잘림에는 유리하다. `10-responsive` 의 잘림 테스트가 계속 통과하는지 확인한다.
- 미리보기는 정적이라 `RepaintBoundary` 로 감싼다. 7개가 스크롤될 때 매번 다시 그릴 이유가 없다.

## 3. 설정 다이얼로그

톱니바퀴 아이콘 하나로 바꾸고, 그 안에 세 가지를 담는다.

```
┌─────────────────────────┐
│ 설정                    │
├─────────────────────────┤
│ 언어            한국어 ›│
│ 진행도 초기화          ›│
├─────────────────────────┤
│ 버전            1.0.0   │
└─────────────────────────┘
```

| 항목 | 동작 |
|---|---|
| 언어 | 지금 언어를 오른쪽에 보여주고, 누르면 기존 `LanguagePickerDialog` 를 연다 |
| 진행도 초기화 | **한 번 더 묻는다.** 되돌릴 수 없다 |
| 버전 | 표시만 |

### 초기화가 지우는 것

**진행도(별점·최고 기록·해금)와 튜토리얼 본 기록을 함께 지운다.** 진행도만 지우면 레벨 1을 다시 깨도 튜토리얼이 안 뜬다 — "처음부터" 가 아니게 된다.

**언어 설정은 지우지 않는다.** 언어는 진행도가 아니라 취향이고, `09` 에서 저장소 접두사를 갈라 둔 이유가 이것이다.

### ⚠ 초기화를 settings 가 실행하면 순환이다

지워야 할 것이 `progress`(진행도)와 `level`(튜토리얼 기록) 양쪽에 있다. `settings` 가 둘을 알면 `level → settings → level` 이 된다.

**다이얼로그는 결과만 돌려주고 실행은 `LevelSelectRoot` 가 한다.**

```
SettingsDialog  →  SettingsResult.resetProgress 반환
LevelSelectRoot →  level usecases(튜토리얼) + progress usecases(진행도) 로 지우고 화면 갱신
```

`level → progress` 는 이미 있고 튜토리얼은 `level` 소유라 새 간선이 없다. **`settings` 는 계속 아무것도 모른다.**

### 버전은 어디서 오는가

`package_info_plus` 를 넣지 않는다. 대신 **`AppConstants.appVersion` 상수 + `pubspec.yaml` 과 일치하는지 검사하는 테스트**를 둔다.

의존성 하나를 아끼자는 것이 아니라, **틀어질 수 있는 값을 테스트가 붙잡을 수 있는 형태로 두는 것**이 요점이다. 상수만 두면 언젠가 어긋나고, 그때는 아무도 모른다.

## 4. 플레이어와 목표를 같은 색으로

**"내가 어디로 가야 하는가" 가 색 하나로 읽혀야 한다.** 지금은 플레이어가 주황, 목표가 청록이라 둘의 관계가 보이지 않는다.

- 플레이어 블록 · 목표 칸을 **파란 계열**로 통일한다.
- **일반 블록 색은 그대로 둔다** (회청색). 플레이어와 헷갈리면 안 되므로 오히려 대비가 커진다.

### 같은 색이면 겹쳤을 때 안 보인다

플레이어가 목표 칸 **위에** 서는 것이 클리어 조건이다. 둘이 같은 색이면 그 순간 목표가 사라진 것처럼 보인다.

→ **목표는 채운 도형이 아니라 링(테두리)으로 그린다.** 같은 색상, 다른 명도·형태.

```
빈 목표 칸        플레이어가 목표에 섰을 때
  ╭───╮              ╭───╮
  │ ○ │              │ ■ │   ← 링 안에 블록이 들어앉은 모습
  ╰───╯              ╰───╯
```

색만으로 구분하지 않으므로 색약 사용자에게도 성립한다.

`BoardColors` 는 `playerBlock` · `goal` 값만 바뀐다. 필드 구조는 그대로다.

## 5. 블랙홀

### 5.1 이름을 전부 바꾼다

`구멍` → `블랙홀`. **표시만이 아니라 규칙서와 코드까지 전부.**

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 기획서 | 구멍 (§2.2 · §3.2 · §3.3 · §3.5 · §4.2) | 블랙홀 |
| 바닥 | `FloorType.hole` | `FloorType.blackHole` |
| 이동 결과 | `MoveResult.fellIntoHole` | `fellIntoBlackHole` |
| 색 | `BoardColors.hole` | `BoardColors.blackHole` |
| 문구 | 5개 언어의 튜토리얼·결과 문구 | 블랙홀로 |

**맵 기호 `X` 는 그대로 둔다.** 7개 맵과 기획서 §9 표기법, 파서 테스트가 전부 이 글자에 걸려 있고, 글자 하나를 바꿔서 얻는 것이 없다.

전부 기계적 치환이라 **컴파일러가 빠진 곳을 잡아준다.**

### 5.2 블랙홀처럼 보이게

```
     ▁▂▃▃▂▁          가장자리  연한 보랏빛
   ▂▓▓███▓▓▂         중간      급격히 어두워짐
   ▃██   ██▃         중심      완전한 검정
   ▂▓▓███▓▓▂         전체      소용돌이 팔 2~3개가
     ▁▂▃▃▂▁                    중심으로 감겨 들어감
```

- **방사형 그라데이션** — 가장자리 연함 → 중심 검정. `RadialGradient` 를 `Paint.shader` 로.
- **소용돌이 팔** — 중심으로 감겨드는 나선 호 2~3개. 바깥일수록 옅게.
- **천천히 계속 돈다.** 한 바퀴 **6초** 정도. 빠르면 시선을 뺏고 어지럽다.

### ⚠ 여기서 처음으로 반복 애니메이션이 필요해진다

지금 이 프로젝트에는 `AnimationController` 가 하나도 없다. 이동 연출은 전부 암시적 애니메이션이고, `06-animation` 이 그렇게 정했다.

블랙홀 회전은 **끝나지 않는 애니메이션**이라 암시적으로는 표현할 수 없다. 여기서만 컨트롤러를 들인다.

**보드 전체를 매 프레임 다시 그리지 않는다.** 페인터를 둘로 나눈다.

```
Stack
├── CustomPaint(BoardPainter)        바닥 · 격자 · 벽 · 목표 — 정적. 지금과 같다
├── CustomPaint(BlackHolePainter)    블랙홀만. 회전값을 받아 매 프레임 다시 그린다
└── AnimatedPositioned 블록들          지금과 같다
```

- 판에 블랙홀이 없으면 **컨트롤러를 아예 돌리지 않는다.** 7개 중 블랙홀이 있는 레벨은 일부다.
- `MediaQuery.disableAnimationsOf` 가 참이면 정지 상태로 그린다.

### 5.3 빨려 들어가는 연출

**플레이어가 블랙홀과 같은 각속도로 회전하면서 축소·소멸한다. 2초.**

- 회전 방향과 속도가 블랙홀과 **같아야** 빨려 들어가는 것으로 읽힌다. 어긋나면 그냥 따로 도는 두 물체다.
- 축소는 선형이 아니라 뒤로 갈수록 빨라진다(`Curves.easeIn`) — 사건의 지평선에 가까울수록 빨라지는 느낌.
- 연출이 **끝난 뒤에** 실패 다이얼로그를 띄운다. 지금도 결과 표시는 연출 뒤이므로(기획서 §7) 구조는 그대로고 시간만 길어진다.

**일반 블록은 지금처럼 0.12초에 사라진다.** 게임이 계속 진행되는 상황이라 한 수마다 2초를 기다리면 답답해진다. 플레이어 소실은 판이 끝나는 순간이라 연출을 길게 줄 이유가 있다.

→ `AppConstants` 에 `playerFallDuration = 2s` 를 새로 둔다. 연출 완료 타이머(`_startAnimationTimer`)가 **빠진 블록에 플레이어가 있는지**를 보고 시간을 고른다.

## 6. 결과 · 튜토리얼 다이얼로그

지금은 화면 전체를 반투명하게 덮고 그 위에 글자를 얹는다. 그래서 **뒤의 판과 글자가 섞여 읽히지 않는다.**

```
지금                          바뀐 뒤
┌────────────────────┐        ┌────────────────────┐
│ ▒▒▒클리어!▒▒▒▒▒▒▒  │        │ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒  │
│ ▒▒▒★★★▒▒▒▒▒▒▒▒▒▒  │        │ ▒  ┌──────────┐ ▒  │
│ ▒▒3수 / 최소 2수▒▒ │        │ ▒  │ 클리어!  │ ▒  │
│ ▒▒[목록][다시][다음]│        │ ▒  │  ★★★    │ ▒  │
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒  │        │ ▒  │ 3수/최소2│ ▒  │
└────────────────────┘        │ ▒  │[목록][다음]│▒  │
   글자가 판 위에 떠 있다      │ ▒  └──────────┘ ▒  │
                              └────────────────────┘
                                 내용만 감싼 카드
```

- 배경 어둡게 덮는 것은 유지(뒤 판이 비쳐야 무엇 때문에 끝났는지 보인다).
- 그 위에 **내용만 감싸는 카드** — `surface` 색, 둥근 모서리, 그림자, `mainAxisSize.min`, `maxWidth` 제한.
- 카드가 살짝 커지며 등장(`AnimatedScale` 0.9 → 1.0).

**여전히 `showDialog` 가 아니다.** Screen 이 Riverpod 도 `showDialog` 도 모르는 채로 남는다는 `04` 의 결정은 유효하다. **다이얼로그처럼 보이는 레이어**일 뿐이다.

### 튜토리얼 오버레이도 같은 카드로 감싼다

둘은 같은 종류의 레이어다 — 판 위에 겹쳐 뜨고, 버튼을 누르면 사라진다. **하나만 카드가 되면 오히려 어긋나 보인다.**

→ **공통 위젯 `OverlayCard` 를 하나 만들고 둘 다 그것을 쓴다.** 배경 스크림 · 카드 · 등장 애니메이션 · `maxWidth` 가 한 곳에 있어야 두 화면이 같이 움직인다.

```
widget/overlay_card.dart      스크림 + 카드 + 등장 연출
├── result_overlay.dart       내용만 담는다
└── tutorial_overlay.dart     내용만 담는다
```

튜토리얼의 두 가지 성질은 그대로 지킨다 — **레이아웃을 차지하지 않는 것**(기획서 §6.1)과 **보드가 뒤에 비치는 것**. 카드로 감싸도 둘 다 유지된다.

## 작업 순서

각 단계 끝에 `fvm flutter analyze && fvm flutter test` 가 통과해야 한다.

| # | 단계 | 왜 이 순서인가 |
|---|---|---|
| 1 | ✅ 기획서 §2·§3·§4 의 `구멍` → `블랙홀` | 규칙 변경은 코드보다 먼저 |
| 2 | ✅ 코드 식별자 일괄 치환 (`FloorType.blackHole` 등) + 5개 언어 문구 | 기계적 치환. 컴파일러가 빠진 곳을 잡는다 |
| 3 | ✅ 색 팔레트 (§4) — 플레이어·목표 파랑, 목표는 링 | 블랙홀 렌더링과 같은 페인터를 건드리므로 먼저 |
| 4 | ✅ 블랙홀 렌더링 + 회전 (§5.2) | 페인터 분리가 여기서 일어난다 |
| 5 | ✅ 빨려 들어가는 연출 2초 (§5.3) | 4가 있어야 각속도를 맞출 수 있다 |
| 6 | ✅ `OverlayCard` + 결과 · 튜토리얼 (§6) | 5의 결과가 이 화면으로 이어진다 |
| 7 | ✅ 설정 다이얼로그 (§3) | 독립적 |
| 8 | ✅ 레벨 그리드 + 미니 보드 (§2) | `BoardPainter` 가 4에서 정리된 뒤라야 재사용이 깔끔하다 |
| 9 | ✅ 스플래시 (§1) | 독립적. 마지막에 붙여도 된다 |

**2를 1보다 먼저 하지 않는다.** 이름이 규칙 문서와 코드에서 갈리는 중간 상태를 만들지 않는다.

## 테스트

| 테스트 | 무엇을 지키는가 |
|---|---|
| 스플래시가 레벨 선택으로 넘어간다 | 시간이 지나면, 그리고 누르면. `go` 라 뒤로가기로 돌아오지 않는다 |
| `level` 이 `game` 을 import 하지 않는다 | **소스 스캔.** 미니 보드를 넣다가 순환을 만들면 여기서 걸린다 |
| 잠긴 레벨의 미니 보드는 실루엣이다 | 판 모양이 스포일러가 되지 않는다 |
| 초기화가 진행도와 튜토리얼을 지우고 **언어는 남긴다** | 접두사를 가른 이유 |
| `AppConstants.appVersion` 이 `pubspec.yaml` 과 같다 | 상수가 조용히 어긋나는 것을 막는다 |
| 블랙홀이 없는 레벨에서는 컨트롤러가 돌지 않는다 | 배터리·성능 |
| 플레이어 소실 연출은 2초, 일반 블록은 0.12초 | 둘을 섞지 않는다 |
| 결과 카드가 화면 전체를 채우지 않는다 | "내용만 감싼다" 의 실질 |
| 결과와 튜토리얼이 같은 `OverlayCard` 를 쓴다 | 한쪽만 손대고 다른 쪽이 어긋나는 것을 막는다 |
| 반응형 27건이 계속 통과한다 | 카드가 커져도 5개 언어 · 큰 글꼴에서 안 깨진다 |

## 열린 질문 / 미결정 사항

- **카드 테두리 색(금·은·동)이 다크 테마에서도 읽히는가.** 금색은 어두운 배경에서 탁해지기 쉽다.
- **미니 보드를 그리면 레벨 선택이 `game` 의 맵 데이터를 전부 읽는다.** 지금은 7개라 무해하지만 레벨이 100개가 되면 목록 진입이 느려질 수 있다. 그때는 화면에 보이는 카드만 그리도록 바꾼다.
- **스플래시를 두 번째 실행부터 줄일 것인가.** 매번 1.8초가 길게 느껴질 수 있다. 지금은 누르면 건너뛰는 것으로 갈음한다.
- **웹 초기 로딩 흰 화면**은 이 작업 밖이다. 별도 과제로 남는다.

## 실제 결과

아홉 단계를 세 번에 나눠 진행했다 — `1~2`(이름), `3~6`(플레이 화면), `7~9`(설정 · 그리드 · 스플래시).

**계획서가 가장 값을 한 곳은 §2와 §3의 순환 경고다.** 둘 다 코드를 짜기 전에 걸렸고, 우회로도 계획서에 이미 적혀 있었다. 미니 보드를 먼저 만들었다면 카드를 다 짠 뒤에 `level → game` 을 발견했을 것이다.

**계획과 달라진 것**

- **`BoardPainter` 를 재사용하지 않고 `BoardPreviewPainter` 를 새로 만들었다.** 계획서는 재사용을 적었지만, 본체는 블록을 그리지 않고(위젯이 얹힌다) 블랙홀도 회전 레이어에 맡긴다. 미리보기는 그 둘이 다 필요하면서 아무것도 움직이지 않는다. 조건을 붙여 합치면 양쪽 다 읽기 어려워진다.
- **카드 테두리를 금·은·동 대신 테마 색(`tertiary` · `primary` · `outline`)에서 뽑았다.** 열린 질문이던 "다크 테마에서 금색이 탁해진다" 를 색을 고정하지 않는 것으로 해소했다.
- **`maxCrossAxisExtent` 160 → 180, `childAspectRatio` 0.85 → 0.72.** 미니 보드가 들어가 카드가 세로로 길어졌다.

**테스트가 실패할 수 있는지 확인한 것이 두 번 값을 했다**

- 오버레이 문구 테스트는 조금 긴 문구로는 실패하지 않았다(줄바꿈된다). 훨씬 길게 만들어 실패를 확인하고 주석을 실제 성질에 맞게 고쳤다.
- **미니 보드 실루엣 테스트는 라우터를 흉내 내고 있어서, 라우터 배선을 망가뜨려도 통과했다.** 진짜 라우터를 태우는 테스트를 따로 추가하고 나서야 교란이 잡혔다.

**남은 것:** 육안 확인. 블랙홀이 블랙홀처럼 보이는지, 스플래시 1.8초가 적당한지, 카드 안 미니 보드가 알아볼 만한 크기인지는 화면으로만 판단할 수 있다.
