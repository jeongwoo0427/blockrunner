# 11. 다국어 (i18n)

## 목표

앱에 하드코딩된 **모든 한국어 UI 문구**를 언어별 Dart 상수 파일로 옮기고, 실행 중에 언어를 바꿀 수 있게 한다.

**지원 언어 5종** — 한국어(`ko`, 기본) · 영어(`en`) · 일본어(`ja`) · 중국어 간체(`zh`) · 프랑스어(`fr`).

**외부 다국어 라이브러리를 쓰지 않는다.** `intl` · `flutter_localizations` · `easy_localization` · `slang` 모두 도입하지 않고, `.arb` 도 코드 생성도 없다. 문자열은 손으로 쓴 Dart 상수이고 언어 선택은 앱이 직접 들고 있는 상태다. 게임 엔진을 쓰지 않는 것과 같은 이유다 — 이 앱이 필요로 하는 것은 "문자열 한 벌을 골라 쓰는 것" 뿐인데, 라이브러리는 코드 생성·빌드 단계·`BuildContext` 규약을 함께 들여온다.

## 선행 조건

- [00-foundation.md](completed/00-foundation.md) — `core/` 골격, `SharedPreferences` 주입
- [08-level-select.md](completed/08-level-select.md) — 마이그레이션 대상 화면이 모두 존재해야 한다

## 1. 무엇이 대상인가

`lib/` 의 한국어 문자열 리터럴은 **두 부류**이고 하나만 번역한다.

| 부류 | 예 | 처리 |
|---|---|---|
| **화면 문구** | `'다시하기'`, `'클리어!'`, `'최소 ${level.minMoves}수'`, 레벨 이름·튜토리얼 | **번역한다** |
| **개발자 메시지** | `map_parser.dart` 의 `'목표 지점이 없다'`, `assert` 문구, `debugMessage`, `toString()` | **그대로 둔다** |

파서 오류는 **레벨을 만드는 사람**이 보는 것이지 플레이어가 보는 것이 아니다. 번역하면 문구가 5배로 늘면서 정작 그것을 읽을 사람에게는 아무 도움이 되지 않는다. 화면에 뜨는 것은 `_ErrorBody` 의 "레벨을 불러오지 못했다" 이고 그 문구만 번역 대상이다 (`debugMessage` 는 그 아래 원문 그대로 붙는다).

### 대상 목록 (전수 조사 결과)

**`game` feature**

| 위치 | 문구 |
|---|---|

## 2. 문자열을 어떻게 표현할 것인가

**추상 클래스 + 언어별 구현.** `Map<String, String>` 를 쓰지 않는다.

```dart
// lib/core/i18n/app_strings.dart
abstract class AppStrings {
  const AppStrings();

  String get reset;            // 다시하기
  String get cleared;          // 클리어!
  String get nextLevel;        // 다음 레벨
  String movesOutOfMin(int moves, int min);   // "3수 / 최소 2수"
  String unlockHint(int levelNumber);         // "2번 레벨을 클리어하면 열린다"
  ...
}
```

```dart
// lib/core/i18n/strings_ko.dart
class StringsKo extends AppStrings {
  const StringsKo();

  @override
  String get reset => '다시하기';

  @override
  String movesOutOfMin(int moves, int min) => '$moves수 / 최소 $min수';
  ...
}
```

이유:

- **키를 빠뜨리면 컴파일이 깨진다.** `Map` 이면 오타가 런타임에 빈 문자열로 나타나고, 그때는 이미 그 언어를 읽는 사람만 볼 수 있다. 추상 멤버는 5개 파일 전부가 구현할 때까지 빌드가 통과하지 않는다.
- **복수형·어순을 각 언어가 스스로 처리한다.** 문자열을 값이 아니라 **함수**로 두면 영어는 `1 move` / `2 moves` 를 자기 파일 안에서 분기하고, 한국어는 분기가 필요 없다. `intl` 의 ICU plural 문법이 하는 일을 Dart 함수가 대신한다. 값이 끼어드는 문구는 전부 함수로 선언한다.
- 상수 인스턴스라 `const` 로 쓸 수 있다.

### 레벨 이름·튜토리얼만 예외 — `Map<int, String>`

레벨은 계속 늘어나므로 레벨마다 추상 멤버를 두면 레벨 하나 추가에 5개 파일 × 2줄이 붙는다.

```dart
@override
Map<int, String> get levelNames => const {1: '미끄러지기', 2: '벽에 기대어', ...};

@override
Map<int, String> get levelTutorials => const {1: '블록은 벽이나 판 끝에...', ...};
```

**컴파일 검사를 잃는 대신 테스트로 막는다** — 모든 언어의 키 집합이 `kLevels` 와 정확히 일치하는지 검사한다(§6). 런타임 폴백은 두지 않는다. 테스트가 통과하면 빠진 키가 존재할 수 없고, 없는 상황을 처리하는 코드는 죽은 코드다.

## 3. 언어 상태 — `settings` feature 신설

### 해석 규칙

```
저장된 선택이 있으면          → 그 언어
없으면 기기 로케일이 지원 목록에 → 그 언어
그것도 아니면                 → ko
```

기기 로케일은 `PlatformDispatcher.instance.locales` 로 읽는다 — **라이브러리 없이 Flutter 프레임워크만으로 된다.** `dart:io` 는 쓰지 않는다(웹에서 못 쓴다).

`zh` 는 기기에서 `zh-Hans-CN` · `zh-CN` 등으로 오므로 **언어 코드만 보고 판정**한다. 번체는 지원 목록에 없으므로 `zh` 로 묶인다 — 별개 언어로 나눌지는 열린 질문이다.

### 구조

새 feature `settings` 를 만든다. 규약(architecture.md §2)의 feature 템플릿을 그대로 따른다.

```
lib/feature/settings/
├── domain/
│   ├── repository/settings_repository.dart      추상
│   └── usecase/
│       ├── settings_usecases.dart               컨테이너
│       └── settings_usecases/
│           ├── get_locale_usecase.dart
│           └── save_locale_usecase.dart         변경을 스트림으로 흘린다
├── data/repository/settings_repository_impl.dart
├── presentation/language_picker/                언어 선택 다이얼로그
└── settings_di.dart
```

- **`AppLocale` 은 `core/i18n/` 에 둔다**, `settings` 의 도메인이 아니다. 문자열 파일이 이 enum 으로 키잉되는데 `core` 가 feature 를 import 할 수는 없다.
- **`SettingsRepositoryImpl` 이 `SharedPreferences` 와 기기 로케일을 함께 들고 있다.** 둘 다 "밖에서 오는 값"이고, `09` 에서 정한 대로 datasource 계층은 두지 않는다. 저장 키는 `settings_v1_locale`.
- **저장은 `progress` 와 섞지 않는다.** 진행도와 설정은 지워지는 시점이 다르다 (`clearAll` 이 언어까지 날리면 안 된다).
- **`SaveLocaleUsecase` 는 스트림을 흘린다** (architecture.md §6). 언어를 바꾸면 화면 전체가 다시 그려져야 하고, 이는 `08` 에서 클리어 결과가 레벨 선택 화면을 갱신한 것과 같은 구조다. **인스턴스는 하나여야 한다** — 두 벌이면 구독자가 조용히 안 울린다(`08` 에서 실제로 겪은 함정).

### feature 의존 방향

```
game  → level, progress
level → progress, settings      ← 언어 선택 UI 를 레벨 선택 화면에서 연다
settings → (없음)
progress → (없음)
```

`settings` 는 아무것도 모른다. **순환이 생기지 않는지가 착수 전 첫 확인 사항이다** — `#22` 와 `#46` 에서 두 번 겪었다.

## 4. 화면이 문자열을 얻는 방법

**`AppStringsScope`(`InheritedWidget`)를 앱 최상단에 두고 `context.strings` 로 읽는다.**

```dart
// lib/core/i18n/app_strings_scope.dart
extension AppStringsContext on BuildContext {
  AppStrings get strings => AppStringsScope.of(this);
}
```

- **Screen 은 여전히 Riverpod 을 모른다** (architecture.md §5). `InheritedWidget` 은 순수 Flutter 라 규약을 어기지 않고, 위젯 테스트에서는 Scope 로 감싸 원하는 언어를 주입하면 된다.
- 문자열 40여 개를 `State` 에 실어 Root → Screen 으로 넘기지 않는다. Screen 아래 `LevelCard` · `GameHud` · 오버레이까지 전부 관통해야 해서 생성자가 무너진다.
- Scope 에 넣을 값은 `main.dart` 의 `BlockRunnerApp` 이 `ref.watch(appStringsProvider)` 로 구독한다. 언어가 바뀌면 `InheritedWidget` 의 값이 바뀌고 아래가 전부 다시 그려진다 — 이것이 "선언해두고 쓴다" 의 실체다.

```dart
// settings_di.dart
final appStringsProvider = Provider<AppStrings>(
  (ref) => stringsFor(ref.watch(localeNotifierProvider)),
);
```

> provider 본문에서 `ref.watch` 를 쓰지 않는다는 규약(§4)의 예외다. 이 provider 는 **DI 배선이 아니라 파생 상태**이고, 언어가 바뀔 때 다시 계산되지 않으면 존재 이유가 없다. 규약 문서에 예외로 명기한다.

### Notifier 가 문자열이 필요한 경우

**필요하지 않게 만든다.** 지금 `GamePlayScreenNotifier` 는 `level.tutorial != null` 로 튜토리얼 표시를 결정하는데, 문구가 번역으로 빠지면 이 판단이 언어에 의존하게 된다.

→ **`Level` 에 `bool hasTutorial` 을 남긴다.** 어느 레벨이 규칙을 가르치는지는 **레벨 데이터의 성질**이지 번역이 아니다. 문구가 없는 언어가 생겨도 튜토리얼이 조용히 사라지면 안 된다.

```dart
// 지금
Level(number: 3, name: '블록을 밟고', minMoves: 3, tutorial: '방향을 입력하면...')

// 바뀐 뒤
Level(number: 3, minMoves: 3, hasTutorial: true)
```

`Level.name` 은 통째로 없앤다 — 모든 레벨이 이름을 가지므로 `strings.levelNames[n]` 이 항상 답을 준다.

## 5. 언어 선택 UI

**설정 화면을 새로 만들지 않는다.** 설정 항목이 언어 하나뿐이라 화면 하나를 세울 근거가 없다.

- **레벨 선택 화면 AppBar 에 언어 아이콘**(`Icons.language`) 하나. 누르면 다이얼로그가 뜨고 5개 중 고른다.
- 다이얼로그는 `settings` feature 소유(`presentation/language_picker/`)이고 레벨 선택 Root 가 띄운다. 스낵바·다이얼로그는 Root 의 책임이다 (architecture.md §5).
- 각 언어 이름은 **그 언어로 적는다** (`한국어` · `English` · `日本語` · `简体中文` · `Français`). 읽을 수 없는 언어로 적힌 목록에서 자기 언어를 찾을 수는 없다.

## 6. 작업 순서

각 단계 끝에 `fvm flutter analyze && fvm flutter test` 가 통과해야 한다.

| # | 단계 | 검증 |
|---|---|---|
| 1 | `core/i18n/` 골격 — `AppLocale`, `AppStrings`, `StringsKo`, `AppStringsScope` | 기존 테스트 전부 통과 (아직 화면은 안 건드림) |
| 2 | `settings` feature — repository · usecase · DI · 로케일 해석 | 해석 규칙 단위 테스트 (저장됨 / 기기 / 미지원 / `zh-Hans-CN`) |
| 3 | `game` · `level` 화면 문구를 `context.strings` 로 교체 | 화면 테스트 전부 통과 + 한글 리터럴 스캔 테스트 |
| 4 | 레벨 데이터 이관 — `Level.name`/`tutorial` 제거, `hasTutorial` 도입 | 튜토리얼 표시 테스트, 레벨↔맵 조인 테스트 |
| 5 | 언어 선택 다이얼로그 + 저장 + 스트림 반영 | 고르면 즉시 바뀌고 재부팅 후에도 유지된다 |
| 6 | `en` · `ja` · `zh` · `fr` 번역 채우기 | 키 패리티 테스트 |

**3번과 4번을 뒤집지 않는다.** 화면이 `strings` 를 통해 문구를 받게 되기 전에 레벨 데이터를 비우면 그 사이 화면에 빈 이름이 뜨고, 중간 상태에서 테스트가 통과하지 않는다.

## 7. 테스트

| 테스트 | 무엇을 지키는가 |
|---|---|
| **한글 리터럴 스캔** | `lib/feature/**/presentation/**` 과 `level_data.dart` 에 한글 문자열 리터럴이 **하나도 없다**. 마이그레이션이 끝났다는 것의 실질적 정의다. `core/i18n/strings_ko.dart` 와 개발자 메시지(data 계층)는 제외 |
| **키 패리티** | 5개 언어의 `levelNames` · `levelTutorials` 키 집합이 `kLevels` 와 정확히 일치한다. 레벨을 추가하고 번역을 빼먹으면 여기서 걸린다 |
| **로케일 해석** | 저장값 우선 / 기기 로케일 / 미지원 → `ko` / `zh-Hans-CN` → `zh` |
| **언어 전환 반영** | 언어를 바꾸면 화면을 나갔다 오지 않아도 문구가 바뀐다 (`08` 의 스트림 테스트와 같은 형태) |
| **usecase 단일 인스턴스** | `SaveLocaleUsecase` 가 한 벌만 존재한다 (`identical`) |
| **Screen 은 여전히 dumb** | 기존 화면 테스트를 `ProviderScope` 없이 `AppStringsScope` 로만 감싸 통과시킨다 |
| **번역이 화면을 깨지 않는다** | 가장 긴 언어로 레벨 카드·HUD·오버레이를 그려 오버플로가 나지 않는다 |

- **`SaveLocaleUsecase` 가 스트림을 흘리지 않는다.** 계획서 §3은 `08` 을 따라 스트림을 두려 했으나, 언어를 들고 있는 곳이 `LocaleNotifier` 하나뿐이고 화면은 전부 `appStringsProvider` 로 거기서 파생된다. 스트림을 두면 같은 사실에 이르는 길이 둘이 되고 어느 쪽이 진짜인지가 흐려진다. `08` 에서 스트림이 필요했던 것은 **서로를 모르는 두 Notifier** 가 있었기 때문이고 여기엔 그런 것이 없다.
- **`SettingsRepositoryImpl` 이 기기 로케일을 함수로 받는다.** `PlatformDispatcher` 를 직접 부르면 테스트가 기기 언어를 못 바꾼다. 값이 아니라 함수인 것은 기기 설정이 앱 실행 중에도 바뀔 수 있어서다.
- **레벨 선택 화면의 언어 아이콘은 `LanguageChangeRequested` 이벤트로 올라간다.** Screen 이 다이얼로그를 직접 띄우면 규약 §5를 어긴다.

**남긴 것**

- `ja` · `zh` · `fr` 번역은 **원어민 검수를 받지 않은 초벌**이다. 각 파일 헤더에 그렇게 적어 뒀다.
- `flutter_localizations` 는 넣지 않았다. Material 위젯 내장 문구가 영어로 남는데, 지금 화면에서 실제로 노출되는 것은 확인되지 않았다.
- CJK 글꼴이 웹에서 깨지는지 육안 확인이 필요하다.

## 열린 질문 / 미결정 사항

- **번역 품질은 누가 보는가.** `en` 은 자신 있지만 `ja` · `zh` · `fr` 은 기계적으로 채운 초벌이다. 특히 레벨 이름은 말맛이 있는 짧은 문구(`보이지 않는 턱`, `지나쳐버리다`)라 직역하면 밋밋해진다. **원어민 검수 전까지는 초벌임을 문서에 남긴다.**
- **`flutter_localizations` 를 정말 한 줄도 안 쓸 것인가.** 안 쓰면 Material 위젯이 자체적으로 갖고 있는 문구(스크롤바 시맨틱, 기본 툴팁 등)는 영어로 남는다. 지금 화면에서 실제로 노출되는 것은 거의 없지만 0은 아니다. SDK 동봉 패키지라 "외부 라이브러리"에 해당하는지도 해석의 여지가 있다 → **일단 넣지 않고, 육안으로 영어가 새어 나오는 곳이 보이면 그때 재검토한다.**
- **중국어 번체(`zh-Hant`)를 나눌 것인가.** 지금은 간체 하나로 묶는다. 대만·홍콩 사용자에게는 다른 언어에 가깝다.
- **글꼴.** CJK 글리프가 기본 폰트로 나오는지는 플랫폼마다 다르다. 웹에서 깨지면 폰트를 번들해야 하는데 그러면 앱 크기가 크게 는다 — 별도 과제로 뺄 수 있다.
- **레벨 이름을 번역하지 않고 두는 선택지도 있었다.** 고유명사처럼 다루는 게임도 많다. 이번에는 번역하기로 했으나, 검수 결과 말맛이 살지 않으면 되돌릴 수 있는 결정이다.
- **`10-responsive` 와의 순서.** 번역문은 한국어보다 길어지는 경우가 많아(특히 프랑스어) 레이아웃을 먼저 다지는 편이 자연스럽다. 다만 `10` 에 남은 것이 검증 성격이라 순서를 강제하지는 않는다.
